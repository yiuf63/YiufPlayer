# UI 评审台（浏览器原型）

DeckPlayer 界面的可交互投影。用来在任意设备上检阅 UI、标注问题、把需求攒成
一份可以直接贴回对话 / issue 的清单。

```
web/ui-review/
├── index.html   控制台骨架（顶栏 / 舞台 / 评审面板）
├── styles.css   控制台样式 + 模拟器内样式（.screen 内 1px = 1 逻辑像素）
└── app.js       四个页面、网格/列表、播放器 OSD、字幕面板、弹层、标注、需求单
```

## 打开

直接双击 `index.html` 即可，没有构建、没有依赖、没有网络请求。

需要分享链接时，在该目录起一个静态服务：

```bash
cd web/ui-review && python3 -m http.server 8899
```

## 这不是第二套实现

原型只做一件事：把 `ui/design.hpp` 与 `src/view/mpv_player.cpp` 里的数值投影成 DOM。
所以它敢用「逻辑像素」当 CSS 像素：

| 原型 | 实机 |
| :--- | :--- |
| `.screen` 宽 1280、高 720 / 800 / 960 | `contentWidth = 1280`，`contentHeight = 1280 × 高/宽` |
| 列表行高 72、缩略图 88×50、标题 17 / 副标题 12.5 | **目标值**，实机 `MediaCell` 现为 76 + 46 图标块 |
| 网格卡片约 248 × 186（列宽随侧栏浮动，不写死） | **目标值**，实机尚无网格实现 |
| OSD 进度条可视高 5 / 命中高 46 | `osd::BAR_H` / `osd::BAR_HIT_H` |
| 主控 64·46·40、设置 40、命中区 48 | `osd::TRANSPORT_D` / `SIDE_D` / `SKIP_D` / `SETTINGS_D` |
| OSD 左右边距 `clamp(w×0.042, 24, 56)` | `osd::marginFor()` |
| 侧栏 160、条目 56、图标 18 + 字号 17 | **目标值**，实机 `sidebar_width` 现为 300 |
| OSD 顶栏 112 / 底栏 168 / 一条工具条 | **目标值**，实机为三行 + 底栏 238 |

缩放只发生在最外层 `.screen` 的 `transform` 上，所以改窗口大小不会改变任何
相对间距 —— 和实机 `windowScale` 的行为一致。

## 信息架构：为什么是「媒体库 / 文件 / 历史 / 设置」

实机原来是「存储位置 / 视频库 / 音乐库 / 播放历史」，四个页面都放内容，
配置项混在里面。问题不是好不好看，是分不清该去哪：

| 原页面 | 问题 |
| :--- | :--- |
| 存储位置 | 既能进目录播视频，又塞着「插件视频源」「插件管理」—— 插件不是存储位置 |
| 视频库 | 塞着「添加媒体文件夹」「重新扫描」—— 这是配置，不是内容 |
| 音乐库 | 与视频库结构完全一样，只换了数据源 |
| 播放历史 | 职责清晰，保留 |

两个入口都能播视频，用户不知道该点哪个；配置项夹在内容中间，每次扫库都要
在影片列表上方找一遍。

现在按「你在这屏要干什么」切分，而不是按「数据从哪来」：

```
媒体库   消费内容：搜索、类型、筛选、网格/列表
文件     按位置找东西：存储设备 → 目录树（MX Player 式）
历史     接着看
设置     一切配置：媒体文件夹 / 内容源与插件 / 字幕 / 外观 / 播放
```

配置项全部从内容页撤出，内容页只剩内容。这条是这一轮改动的核心，其余都是配套。

## 媒体库怎么组织：一层文件夹 + 一个视图菜单

把四五个媒体文件夹的内容全部拉平，视频和音乐混在一条列表里，十个「01. 开头」
的文件排成一列 —— 找东西只剩搜索。MX Player 的处理是给列表加一层文件夹，
并把「怎么显示」收进一个单独呼出的菜单。这里照做：

```
媒体库
├── 文件夹（默认）      每个目录一张卡：四宫格拼贴 + 计数 + 「N 个视频 · N 首音乐」
│   └── 进入目录后       按视频 / 音乐分区，顶部有「全部文件夹」返回行
├── 全部平铺            所有内容一条一条排，仍然分成视频段与音乐段
└── 最近添加            固定 8 条，跨文件夹取最新的，不跟排序选项变
```

**入口只有一个**：工具行右侧的「按文件夹 · 名称」按钮。点开是四组选项：

| 组 | 选项 | 说明 |
| :--- | :--- | :--- |
| 分组 | 按文件夹 / 全部平铺 | 结构怎么切 |
| 内容 | 视频与音乐 / 仅视频 / 仅音乐 | 要哪一类 |
| 排序 | 名称 / 最近添加 / 时长 / 大小 | 段内怎么排，配合升降序 |
| 筛选 | 不限 / 未看完 / 已看完 | 只看特定进度 |

**为什么不是一排胶囊**：上一版把「视频 / 音乐 / 全部」和四个筛选胶囊摊在工具行上，
58px 的带子被占满，能表达的只有五个词；四组选项塞进去会变成两行。收进菜单之后
工具行只剩搜索框、入口和命中数。

**为什么平铺也分区**：真混排时「3:21」既可能是短片也可能是歌。所以平铺状态下
视频和音乐各成一段，音乐卡片另加 ♪ 类型标；要真正按目录归拢就切回文件夹视图。

## 这一版领先于实机

1. **信息架构重排**（上面一节）。实机四个 Tab 在 `createContentView()` 里。
2. **媒体库的分组与视图菜单**。实机 `FileBrowserActivity` 现在只有一条扁平的
   视频列表 + 一条音乐列表，没有文件夹层，也没有排序 / 筛选入口。
3. **侧栏 300 → 216 → 160**（1280 的 12.5%）。纯文字时 216 仍显空 —— 汉字只占
   51px，右边一大片没东西，所以“太宽”的根子是内容撑不起来。加 18px 图标后
   再收到 160，密度反而更高。
4. **OSD 底栏 238 → 168，三行压成一条工具条**。原来主控行居中、设置行右对齐、
   时间单独一行，三条对齐轴互不相干，左下角整片空着。现在主控块左缘贴 `m`、
   设置块右缘贴 `w−m`，时间并进进度条两端，只剩两条轴。
5. **列表行加 16:9 缩略图**（88×50），进度条压进缩略图底边。网格卡片约 248 宽。
6. **字幕面板 + 字幕文件选择器**。这条已经在实机落地（`FilePickerActivity`）。
7. **新增浅色主题**（深色 → OLED → 浅色三态）。浅色只作用于浏览界面，
   播放页 OSD 永远暗色 —— 亮底控件压在亮画面上会直接消失。

实机落地前，上表的「目标值」不等于「现状」；落地后要把这一节删掉，并把
`docs/UI-DESIGN.md` 里的数值一并更新。

## 看什么

- **媒体库**：默认是文件夹总览（四宫格拼贴 + 计数），下面是「最近添加」。
  工具行右侧「按文件夹 · 名称」打开视图菜单：分组 / 内容 / 排序 / 筛选 + 升降序。
  `V` 或 `Y` 也能开合。进目录按 `Esc` 回总览。
- **文件**：内置存储 / SD 卡 → 目录。`Downloads` 是特意留的空文件夹，用来看空态。
- **设置**：13 项分五组。字幕那组有两条实机还没有的能力，都带风险标记。
- **播放器 OSD**：点字幕按钮（或按 `S`）打开字幕面板 —— 轨道列表、加载外挂字幕、
  字幕延时。点「从文件加载…」是文件选择器，默认停在当前视频目录、只列字幕扩展名。
- **设备**：Deck 1280×800、1080p、640×480 掌机、4:3 平板。切换后底部会算出
  物理缩水：640 宽设备上 12.5 的字只有 6.25 物理像素，44 的触控目标只有 22px。
- **缩放**：手机竖屏整体只有 0.28 倍，看不清字号。切「1:1」按逻辑像素真实
  大小渲染，舞台可左右拖动，用来核对具体尺寸。
- **画面测试**：暗场 / 亮场 / 彩条，用来压 OSD 的对比度。亮场下未播放的进度条
  轨道会接近消失，这条已经列进「待确认」。
- **标注**：给每个关键元素画虚线框和风险点。点一下，右侧显示它的实际尺寸、
  位置、规格出处；再点「针对这里提需求」就能把意见挂到具体元素上。
- **需求单**：存在浏览器 localStorage，可导出 Markdown（同时复制并下载）。

## 操作

| 操作 | 键盘 / 鼠标 |
| :--- | :--- |
| 移动焦点 | `↑` / `↓`（网格里按一行 4 个跳） |
| 切换侧栏 ↔ 内容 | `←` / `→`（网格里先横向换卡片） |
| 确认 | `Enter` |
| 视图菜单 | `V`，`Esc` 收起 |
| 进入 / 退出文件夹 | `Enter` / `Esc` |
| 搜索 | 直接点搜索框输入，`Esc` 清空 |
| 打开 / 收起 OSD | 点画面空白处，或 `O` |
| 播放 / 暂停 | 双击画面，或 `Space` |
| 快退 / 快进 10s | `←` / `→`（播放器内） |
| 音量 / 亮度 | 滚轮 / `Shift` + 滚轮（播放器内） |
| 字幕面板 / 音轨 / 播放列表 | `S` / `A` / `P`（播放器内） |
| 锁定 / 解锁 | `L`，或双击画面解锁 |
| 标注模式 | `N` |
| 评审面板 | `D` |

## 原型与实机的差异（有意为之）

- 字体用系统字（PingFang / Noto），实机是内置中文字体，字宽会略有差别。
- 视频画面是 CSS 渐变 + 噪点，不是真实解码帧。
- **缩略图是 CSS 画的场景示意**（地平线 / 天光 / 斜射光 / 暗角），不是视频帧。
  原型不引 ffmpeg.wasm：接入成本远大于它带来的评审价值。8 套色相是为了避免
  「一屏 3 行看出循环重复」，实机会是 8 张完全不同的真实画面。
- 字幕文件选择器只列 `SUB_FILES` 里的 5 个假文件，没有真正的目录遍历。
- 设置页大部分条目只占位（`set-*` 会提示「等实机功能定了再做面板」）。
- 实机 OSD 用 nanoVG 逐帧绘制，这里用 DOM；动画时长（240ms OSD、260ms HUD
  淡出）一致，但缓动函数是 CSS 近似。

## 缩略图为什么要取 10% 而不是第一帧

片头黑场、淡入、发行方 logo 前的全黑都很常见，抽「第一帧」会让整面网格有一半
是黑的。Plex / Jellyfin 的默认策略是 `min(时长 × 0.1, 30s)`，本项目照此实现：

- 抽帧位置 `min(duration * 0.1, 30.0)` 秒
- 输出 320 × 180 JPEG，落到 `~/.cache/deck-player/thumbs/<hash>.jpg`
- 主程序目前只链了 `MPV_LIBRARIES`，直接抽帧需要显式链接
  avformat / avcodec / swscale（FFmpeg 本来就在，由 libmpv 带入）

## 字幕：已经在实机落地

原来 `promptLoadExternalSubtitle()` 弹 IME，让用户在掌机上敲
`/run/media/mmcblk0p1/Videos/...`。现在已经改成文件选择器（提交 `c70b83f`）：

```cpp
FilePickerActivity::files({".srt", ".ass", ".ssa", ".vtt", ".sup"},
                          dir, prefix, "选择字幕文件", [this](auto& p) {
                              loadExternalSubtitle(p);
                          });
```

`File` 模式只列匹配扩展名，默认停在**当前视频所在目录** —— 同名字幕 90% 的情况
已经在那里了，与片名匹配的排最前并标「同名」。`folders()` 工厂保留原来的
「添加媒体文件夹」行为。

原型这边的差别：字幕面板（轨道列表 / 加载外挂 / 延时 ±0.5s）还只是 UI，
实机目前只有 `sub-add` 的加载逻辑，没有面板。

扫描时 `MediaItem::matched_subtitles` 其实已经被填上了（卡片上显示「含字幕」），
数据有、动作没接，所以「自动加载同名外挂字幕」也只是一行配置的事。

其余颜色、字号、间距、圆角、命中区均按代码取值。若发现原型与实机不一致，
以实机代码为准，并回来修这份投影。
