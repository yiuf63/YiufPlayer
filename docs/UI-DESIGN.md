# UI 与交互设计规格

本文件定义 DeckPlayer 的界面规格与交互约定。**新增界面时必须遵守**，
避免各处硬编码字号/间距导致观感不一致（这是重构前的主要问题）。

---

## 1. 设计目标

| 项 | 决定 | 理由 |
| :--- | :--- | :--- |
| 主输入 | **触屏优先**，手柄对等 | 目标设备是平板与掌机；手柄和触屏必须都能完成全部操作 |
| 布局基准 | 逻辑尺寸 **1280 × 906** | borealis 的 `contentWidth/Height`；所有数值以此为单位 |
| 缩放 | 由 `windowScale` 自动换算到物理像素 | 不假设设备分辨率 |
| 主题 | 仅深色 | 播放器多在暗环境；也避免两套配色维护成本 |

### 两条硬性规则

1. **触控目标最小 44 × 44 逻辑像素**。小于此值只能靠手柄，触屏不可用。
2. **任何操作都必须有触屏路径**。手柄提示文字不能是唯一的入口说明。

## 3. 颜色

| 语义 | 值 | 用途 |
| :--- | :--- | :--- |
| 背景 | `#14161A` | 页面底色 |
| 侧边栏 | `#1A1C21` | 比背景略亮，自然分层 |
| 高亮块 | `#22262D` | 列表项选中 |
| 强调 | `#FF9F45` | 焦点框、进度、主按钮 |
| 强调（亮） | `#FFC07A` | 悬停、渐变高光 |
| 主文字 | `#F2F2F5` | |
| 次文字 | `#8A8F98` | |
| 禁用 | `#505358` | |
| 视频遮罩 | `rgba(0,0,0,0.75)` | OSD 渐变底 |

**对比度**（按 WCAG 公式实算）：主文字对背景 **16.2:1**，次文字 **5.6:1**，
强调橙 **8.9:1**，均满足 AA（≥4.5:1）。
注意：侧边栏对背景仅 **1.06:1**、高亮块 **1.19:1** —— 作为「分层底纹」可接受，
但**不能承载信息**，选中态必须另有强调色竖条或加粗文字。

## 4. 图标

**不使用 emoji。** 原因：emoji 由系统字体渲染，同一字符在
macOS / Android / 掌机上形态与尺寸差异极大，部分设备直接显示为方框
（实测本项目的 `📁 🔄 🗑 ⚙️` 在 Android 上不可靠）。

统一使用 `resources/font/icon.ttf`（Material Icons 子集）。
用法：`setText("\ue2c7")` 之类的码位，或封装成 `Icon::folder()` 常量。

> 迁移期间的临时妥协：若某图标在 icon.ttf 中不存在，用**纯文字**代替
> （如「添加」而非 `➕`），不要退回 emoji。

## 5. 播放器 OSD

### 布局（自下而上）

```
┌─────────────────────────────────────────────┐
│  片名                         ⚡ 硬解  20:31 │  顶部 65px，渐变消失
├─────────────────────────────────────────────┤
│                                             │
│                 视频画面                     │
│                                             │
│         ┌─────────────────┐                 │
│         │   HUD 提示       │                 │  居中，操作后短暂出现
│         └─────────────────┘                 │
│                                             │
├─────────────────────────────────────────────┤
│  ●───────────────────────────────────────   │  进度条：可视 8，触摸区 44
│  00:12                            01:30     │
│  [⏪] [⏯] [⏩] [音轨] [字幕] [比例] [列表]   │  按钮行 56px
└─────────────────────────────────────────────┘  底部 110px，渐变消失
```

### 交互

| 操作 | 触屏 | 手柄 |
| :--- | :--- | :--- |
| 显示/隐藏 OSD | 单击画面空白 | — |
| 播放/暂停 | 双击画面，或点 ⏯ | A |
| 拖动进度 | **按住进度条拖动** | ← → |
| 快退/快进 10s | 点 ⏪ / ⏩ | LT / RT |
| 音量 | 右半屏上下滑 | — |
| 亮度 | 左半屏上下滑 | — |
| 音轨 | 点「音轨」 | X |
| 字幕 | 点「字幕」 | Y |
| 比例 | 点「比例」 | — |
| 倍速 | 点「倍速」按钮 | R3 |
| 锁定 | 双击锁图标 | — |
| 返回 | 系统返回键 | B |

### OSD 自动隐藏

- 显示后 **8 秒**无操作则隐藏（原为 5 秒，太短）
- **拖动进度条期间不隐藏**，松手后重新计时
- 隐藏时**清空触摸命中区**，避免点到看不见的按钮

### 结构

```
┌──────────┬──────────────────────────────────┐
│ 存储位置 │  媒体文件夹                       │
│ 视频库   │  ┌────────────────────────────┐  │
│ 音乐库   │  │ 📁 影片    /sdcard/Movies  │  │
│ 播放历史 │  └────────────────────────────┘  │
│          │  视频 (118)                       │
│          │  ┌────────────────────────────┐  │
│          │  │ 01. 漂流 冒険の島!.mkv      │  │
│          │  │    24:13 · 1.2 GB          │  │
│          │  └────────────────────────────┘  │
└──────────┴──────────────────────────────────┘
```

- 侧边栏宽 1/5（≈256），内容区自适应
- 列表项：主文本（文件名）+ 次文本（时长 · 大小）
- 焦点/选中：高亮块 `#22262D` + 左侧 4px 强调色竖条

### 空状态

每个标签页在无数据时必须显示**可操作**的提示，而不是空白：

| 标签 | 空状态文案 | 附带操作 |
| :--- | :--- | :--- |
| 存储位置 | 尚未添加媒体文件夹 | 「添加媒体文件夹」按钮 |
| 视频库 | 没有找到视频文件 | 「重新扫描」按钮 |
| 音乐库 | 没有找到音乐文件 | 「重新扫描」按钮 |
| 播放历史 | 还没有播放记录 | 无 |

### 触摸控件入口（重构后）

**主控行**（居中）：上一集 · -10s · 播放 · +10s · 下一集
**功能行**（右对齐）：音轨 · 字幕 · 倍速 · 画面 · 锁定

播放按钮用强调色实心填充，是唯一的「主操作」视觉焦点。

### 踩到的坑：可变字体导致整帧渲染失败

换字体时选了 **Noto Sans SC 可变字体（VF）**，现象是：

```
有中文文字的 OSD  → 视频区域 100% 纯黑
去掉中文文字      → 视频正常
```

**根因**：nanoVG 的 `stb_truetype` 不支持可变字体（`fvar` 表）。
渲染中文时字形解析失败，**整个 nanoVG 帧被丢弃**，
于是 mpv 已经画好的视频也被一并丢弃 —— 表现为「加个中文标签，视频就没了」。

排查方式：二分（只画文字 / 只画按钮 / 两组都画），
配合「高饱和像素占比」判断视频是否真的在。

**修复**：用 `fonttools` 的 `instantiateVariableFont` 把可变字体
实例化到 `wght=400`，得到静态 TrueType 字体：

```python
from fontTools.ttLib import TTFont
from fontTools.varLib.instancer import instantiateVariableFont
f = TTFont('variable.ttf')
inst = instantiateVariableFont(f, {'wght': 400}, inplace=False)
inst.save('static.ttf')       # 无 fvar、有 glyf、无 CFF
```

**选字体的三条硬性要求**（缺一不可）：

| 要求 | 检查方式 | 违反后果 |
| :--- | :--- | :--- |
| 无 `fvar` 表 | fontTools `'fvar' in f.keys()` | 整帧渲染失败 |
| 有 `glyf` 表（TrueType 轮廓） | `'glyf' in f.keys()` | CFF/OTTO 不支持 |
| 覆盖中文 | `len(cmap)` 中 CJK ≥ 20000 | 缺字显示为方块 |

`scripts/check_font.py` 可一键校验这三条。

### 关于 emoji

原实现用 `📁 🎬 🎵 📂 🔄 🗑 ⚙️ ➕ 🔒` 作为列表前缀。
这些由**系统 emoji 字体**渲染，在 Android 上形态差异极大，部分设备显示为方框。

另外 `resources/font/icon.ttf` 只有 1028 个码位，Material Icons 大部分缺失
（`folder`/`settings`/`delete`/`search` 等都没有），**无法作为替代方案**。

因此统一改为纯文字前缀：`[文件夹]` `[视频]` `[音乐]` 等。
观感朴素但不依赖任何字体。

## 10. 审计发现与修复（第 44 轮）

一次独立审计（逐行读码 + 抓帧实测）发现了三个**致命**问题，都是之前
84 项自动检查抓不到的。记录在此，作为「检查项要覆盖什么」的教训。

### 缺陷 1：OSD 所有文字都画不出来

```cpp
nvgFontFace(vg, "sans");      // ← "sans" 从未注册过
```

`"sans"` 是 nanoVG 官方示例里的名字，本项目注册的是 `regular` / `zh-Hans` /
`emoji` / `switch`。fontstash 查不到就返回 `-1`，`nvgText` 随即直接 return。

**后果**：片名、时间、按钮标签、手柄提示**全部不可见**，
用户只看到一排空色块 —— 这正是「控件只有按钮、样式不对」的真正原因。

**修复**：改用 `nvgFontFaceId(vg, brls::Application::getDefaultFont())`。

**为什么 84 项检查没抓到**：它们只验证「视频有没有画面」「界面有没有亮像素」。
主界面有文字，所以「有亮像素」通过；OSD 是空白，但没人验证过它。

**新增守卫**：`verify_ui.py --only osd`（5 项）。
用**纯黑视频**做底，任何白/蓝/橙像素都只可能来自 OSD 本身。
实测把字体名改回 `"sans"` 后，白像素立刻变 0，两项检查变红 —— 证明它有效。

### 缺陷 2：进度条被主控按钮完全盖住

```
进度条 y:      652~660
进度条判定区:  634~678
主控行 y:      639.8~698.0     ← 与判定区竖直重叠 38px
```

用户既看不见进度条也拖不动它。而 `BOTTOM_H=110` 只够放一行按钮，
功能行（y=564）整个画到了视频画面上。

**修复**：`BOTTOM_H` 提到 215；进度条改为自底部往上定位
（`height - BAR_BOTTOM_PAD - BAR_H`），按钮行排在进度条上方。
实测三层不重叠：

```
y=560-568  功能行文字
y=616-664  主控行按钮（橙色描边）
y=696-704  时间文字 + 进度条（蓝色）
```

### 缺陷 3：A 键被 `registerClickAction` 覆盖

borealis 的 `registerAction` **按按钮去重**（`view.cpp:770-774`），
后注册的会直接覆盖先注册的：

```cpp
registerAction(BUTTON_A, 播放/暂停);   // 先
registerClickAction(切换 OSD);         // 后，内部也是 BUTTON_A → 覆盖
```

**后果**：手柄按 A 不会暂停，只切 OSD。

**修复**：OSD 切换不再用 `registerClickAction`（触屏单击已由
`TapGestureRecognizer` 处理），手柄侧保留 A = 播放/暂停。

### 顺带修的两个

| 问题 | 修法 |
| :--- | :--- |
| `has_locked_action_` 声明后从未赋值，按钮无按下态 | 在 Tap `START` 时置真、`END` 时清除 |
| `TouchAction::Playlist` 是死分支（无按钮引用） | 功能行加「列表」按钮 |

### 教训：检查项决定了能看到什么

| 已有检查 | 能发现 | 发现不了 |
| :--- | :--- | :--- |
| 单元测试（8 套） | 逻辑错误 | 任何 UI 问题 |
| 抓帧像素统计（79 项） | 崩溃、黑屏、视频没渲染 | **文字是否可读**、控件是否重叠 |
| 新增 OSD 检查（5 项） | 文字不可见、控件重叠 | 交互是否真的响应 |

**下一层缺口**：目前没有任何自动化检查注入过**触摸事件**
（`functional_smoke.cpp` 只注入 `BUTTON_A`）。「手指点列表项能不能打开视频」
至今只靠人工验证。
