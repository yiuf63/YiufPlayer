# UI 与交互设计规格

本文件是 DeckPlayer 界面的**唯一视觉标准**。新增界面必须引用设计 token，
不得再写字面量颜色 / 字号 / 圆角 —— 那正是重构前「一屏五种字号、三种边距、
方括号前缀加 emoji」的拼装观感来源。

| 相关代码 | 作用 |
| :--- | :--- |
| `include/ui/design.hpp`、`src/ui/design.cpp` | 色板 / 间距 / 圆角 / 字号 / 绘制基元 |
| `include/ui/icons.hpp`、`src/ui/icons.cpp` | 32 个矢量图标（nanoVG 路径） |
| `include/view/media_cell.hpp`、`src/view/media_cell.cpp` | 卡片行 / 分组标题 / 空态 |
| `src/view/mpv_player.cpp` | 播放器 OSD |
| `src/theme/deck_theme.cpp` | borealis 侧边栏 / 焦点框 / 头部度量覆盖 |
| `web/ui-review/` | 浏览器里的可交互评审原型（1:1 逻辑像素） |

> 原型不是第二套实现。它只把本文件的数值投影成 DOM，用于在电脑 / 手机 / 平板上
> 随时检阅并记录需求；任何视觉决定仍以本文件与 `ui/design.hpp` 为准。
> 打开方式：直接双击 `web/ui-review/index.html`，或在目录内起一个静态服务器。

## 1. 设计目标

| 项 | 决定 | 理由 |
| :--- | :--- | :--- |
| 主输入 | **触屏优先**，手柄对等 | 目标设备是平板与掌机；两条路径都要能走完全部操作 |
| 参照系 | 电视端影音软件 | 不是游戏机系统菜单，也不是移动端 App |
| 坐标单位 | **逻辑像素**，宽度恒 1280 | `contentWidth` 固定 1280，高度由设备宽高比决定（见 1.1） |
| 缩放 | `windowScale = 物理宽 / 1280` | 不假设设备分辨率 |
| 主题 | 深色 / OLED 真黑两套 | 播放器多在暗环境；OLED 用纯黑省电且无光晕 |

### 四条硬性规则

1. **触控目标最小 44 × 44 逻辑像素**。小于此值只能靠手柄。
2. **任何操作都必须有触屏路径**，手柄提示文字不能是唯一入口说明。
3. **一个字面量都不许写**：颜色 → `ui::palette()`，间距 → `ui::space`，
   圆角 → `ui::radius`，字号 → `ui::font`。
4. **画面上不堆文字**。播放控件一律用图标，文字只承担「片名 / 时间 / 数值」。

### 1.1 坐标系与它的边界

没有「布局基准分辨率」这回事 —— 设备差别太大，写死一个尺寸只会让另一类设备错位。
真正需要固定的是**单位**：

```
contentWidth  = 1280                      // 恒定
contentHeight = 1280 × 物理高 / 物理宽     // 16:9→720，16:10→800，4:3→960，竖屏→2048
windowScale   = 物理宽 / 1280
```

所以所有 token（44 / 238 / 12.5）的单位是「宽度 1280 时的像素」，**不是一个固定的
1280×906 画布**。布局按高度锚定（底栏贴底、顶栏贴顶），宽度锚定 1280 —— 这样
16:9 与 4:3 都不需要 letterbox。

**这条模型的代价必须写清楚**：`windowScale` 同时缩放字号与触控目标，
所以「44 逻辑像素」只在宽度 1280 的设备上才真的是 44 物理像素。

| 设备 | 物理宽 | `windowScale` | 44 逻辑 = | 12.5 字号 = |
| :--- | ---: | ---: | ---: | ---: |
| Steam Deck | 1280 | 1.00 | 44 px（≈6.1 mm） | 12.5 px |
| 16:9 平板 | 1920 | 1.50 | 66 px | 18.8 px |
| 640×480 掌机 | 640 | 0.50 | **22 px（≈3.5 mm）** | **6.25 px** |

小屏上触控目标与字号一起缩水到不可用。目前靠「该档设备没有触摸屏」躲过触控问题，
但**文字可读性没有躲过** —— 见第 11 节。

### 1.2 信息架构

页面按「你在这屏要干什么」切分，不按「数据从哪来」切分。

| 页面 | 职责 | 内容 |
| :--- | :--- | :--- |
| 媒体库 | 消费内容 | 文件夹（默认）/ 全部平铺、最近添加；搜索 + 一个视图菜单（分组/内容/排序/筛选） |
| 文件 | 按位置找东西 | 存储设备 → 目录树（MX Player 式），不受媒体库扫描范围限制 |
| 历史 | 接着看 | 继续观看列表 |
| 设置 | 一切配置 | 媒体文件夹、内容源与插件、字幕、外观、播放 |

**为何不用原来的四页。** 改动前实机（`createContentView()`）是
「存储位置 / 视频库 / 音乐库 / 播放历史」，问题不在美观：

| 原页面 | 问题 |
| :--- | :--- |
| 存储位置 | 既能进目录播视频，又塞着「插件视频源」「插件管理」—— 插件不是存储位置 |
| 视频库 | 塞着「添加媒体文件夹」「重新扫描」—— 这是配置，不是内容 |
| 音乐库 | 与视频库结构相同，只是换了数据源 |
| 播放历史 | 职责清晰，保留 |

两个入口都能播视频，用户不知道该点哪个；配置项夹在内容中间，每次扫库都要
在影片列表上方找一遍。所以：

1. **配置项一律从内容页撤出**，内容页只剩内容。
2. **「按位置浏览」独立成页**，与「按内容聚合」分开 —— 这两件事的心智完全不同。
3. 视频与音乐合并进「媒体库」，用类型切换而不是两个平行页面。

#### 落地进度（2026-11）

| 项 | 状态 |
| :--- | :--- |
| 侧栏 300 → 160，条目 56 + 18px 图标，四页改名重排 | 已落地 |
| 音乐并入媒体库（分段，不是混排），独立音乐页删除 | 已落地 |
| 设置页收纳「重新扫描 / 清空缓存 / 插件管理 / 关于」 | 已落地 |
| 媒体库文件夹层 + 四宫格目录卡 + 最近添加 | 已落地（`MediaFolderCard`） |
| 视图呼出菜单（分组 / 内容 / 排序 / 筛选） | 未落地，仍在原型 |
| 网格视图（「全部平铺」的四列缩略图墙） | 未落地，仍在原型 |
| 播放页 OSD 两行布局、字幕面板 | 未落地，仍在原型 |

#### 媒体库内部：一层文件夹 + 一个视图菜单

把四五个媒体文件夹的内容全部拉平，视频和音乐混在一条列表里，十个「01. 开头」
的文件排成一列 —— 找东西只剩搜索。MX Player 的解法是给列表加一层文件夹，
并把显示规则收进一个单独呼出的菜单。本项目照此实现：

| 结构 | 行为 |
| :--- | :--- |
| 文件夹（默认） | 每目录一张卡：四宫格拼贴 + 计数角标 + 「N 个视频 · N 首音乐」；进入后按视频/音乐分区 |
| 全部平铺 | 一条一条排，仍分视频段与音乐段；音乐卡片带 ♪ 类型标 |
| 最近添加 | 固定 8 条，跨文件夹取最新的；不跟着排序选项变 |

**入口只有一个**：工具行右侧按钮（显示当前摘要，如「按文件夹 · 名称」），
呼出菜单包含四组：分组 / 内容 / 排序 / 筛选，外加升序降序与恢复默认。

> **为什么不做成一排胶囊。** 四组选项塞进 58px 高的工具行会变成两行，
> 而且「视频/音乐/全部」这种词占着位置却表达不了排序。菜单的价值是
> **入口只有一个、里面可以分组**，工具行因此只剩搜索框、入口和命中数。

> **为什么平铺也分区。** 真混排时「3:21」既可能是短片也可能是歌。分区 +
> 类型标之后一眼能分；要按目录归拢就切回文件夹视图。

**实机进度**：文件夹层与目录卡已经落地 —— `MediaLibrary::getGroups()` 按用户
添加的文件夹归组（嵌套目录归最近的一层），首屏是「文件夹 · N」四列目录卡 +
「最近添加 · 8」；进入文件夹后是「全部文件夹」返回行 + 视频段 + 音乐段，
B 键在这一层是「退回总览」，不会退出界面。

排序 / 筛选 / 平铺这三项仍只在原型里：实机还没有视图菜单，条目顺序固定为
名称序，平铺视图也没做。

> **四宫格现在画的是什么。** 还没有抽帧管线，所以每格是「天空渐变 + 落日 +
> 两道山脊」的占位画面（按路径哈希取色，同一文件每次恒定）。保留山脊是因为
> 人眼靠**轮廓**认画面：纯渐变会糊成一块发光色斑，加了轮廓才读得出「这里
> 装着四部片子」。抽帧落地后只换 `drawTile()` 的填充，卡片尺寸与交互不动。
>
> 项数不足 4 的目录不补空格子，改成等分竖条（2–3 条）：空格子会被读成
> 「这里有东西没加载出来」，比少画一格更像故障。

## 2. 设计 token

### 2.1 字号（只有五级）

| token | 值 | 用途 |
| :--- | ---: | :--- |
| `font::display` | 26 | 页面主标题 |
| `font::title` | 20 | 分组大标题 / 播放器片名 |
| `font::body` | 17 | 列表行主文字、按钮标签 |
| `font::detail` | 14 | 副文字、元信息、时间 |
| `font::caption` | 12.5 | 最小说明文字、分组标题 |

**禁止第六种字号。** 需要「更大」时改布局（加留白、加图标），不改字号。

### 2.2 间距（4 的倍数）

| token | 值 | 用途 |
| :--- | ---: | :--- |
| `space::xs` | 4 | 图标与文字之间的贴合距离 |
| `space::sm` | 8 | 行内元素间距 |
| `space::md` | 12 | 卡片内边距、列表行间距 |
| `space::lg` | 16 | 卡片左右内边距、区块内间距 |
| `space::xl` | 24 | 区块之间 |
| `space::xxl` | 32 | 页面外边距、大区块之间 |

### 2.3 圆角

| token | 值 | 用途 |
| :--- | ---: | :--- |
| `radius::sm` | 8 | 小徽标、进度条端点 |
| `radius::md` | 14 | **卡片、焦点框**（全局统一） |
| `radius::lg` | 20 | 对话框、居中 HUD |
| `radius::pill` | 999 | 胶囊按钮、圆形按钮 |

## 3. 调色板

`ui::palette()` 返回当前主题的色板，由 `ThemeKind::{Dark, Oled}` 决定，
切换方式见第 8 节。

### 3.1 标准深色（默认）

| 语义字段 | 值 | 用途 |
| :--- | :--- | :--- |
| `bg` | `#0F1114` | 页面底色 |
| `surface` | `#181B20` | 一级卡片（列表行、面板） |
| `surfaceRaised` | `#21252C` | 二级表面（悬停 / 选中 / 弹层） |
| `surfaceSunken` | `#2A2F37` | 凹陷（进度轨道底、图标占位块） |
| `outline` | `rgba(255,255,255,0.08)` | 细描边 |
| `outlineStrong` | `rgba(255,159,69,0.55)` | 选中态描边 |
| `text` | `#F3F4F6` | 主文字 |
| `textDim` | `#A8AFBA` | 副文字 |
| `textMute` | `#717884` | 辅助信息（时间、路径、分组标题） |
| `accent` | `#FF9F45` | 唯一强调色 |
| `accentInk` | `#1A1206` | 强调色上的文字（深色） |
| `accentSoft` | `rgba(255,159,69,0.16)` | 图标底、胶囊底 |
| `danger` | `#F0616D` | 错误 |
| `scrim` | `#000000` | 视频遮罩底色（配 alpha） |

### 3.2 OLED 真黑

Steam Deck OLED、TrimUI Smart Pro 等 AMOLED 设备上，`#000000` 的像素完全不耗电
且无光晕。层级步进刻意收小 —— A 屏对比度高，大步进会重新产生「灰底」观感。

| 语义字段 | 值 |
| :--- | :--- |
| `bg` | `#000000` |
| `surface` | `#0B0C0F` |
| `surfaceRaised` | `#15171B` |
| `surfaceSunken` | `#1E2126` |

强调色与文字与标准深色一致：省电的是底色，不是内容。

### 3.3 对比度

按 WCAG 公式实算（标准深色）：主文字 **16.2:1**、次文字 **5.6:1**、
强调橙 **8.9:1**，均满足 AA（≥4.5:1）。
`surface` 对 `bg` 仅约 **1.15:1** —— 作为分层底纹可接受，
但**不能承载信息**：选中态必须另有强调色描边或竖条。
这也是 `MediaCell` 用「底色 + 描边 + 左侧竖条」三重强调的原因。

### 3.4 强调色的使用纪律

强调色**只在三处出现**：主操作按钮、当前选中项、进度指示。
列表里的次要按钮（音轨 / 字幕 / 倍速）用它做**底色的低透明度版本**
（`accentSoft`），不用纯色，否则一屏里全是橙色反而没有焦点。

## 4. 图标

**不使用 emoji，也不使用字体图标。**

| 方案 | 问题 |
| :--- | :--- |
| emoji | 由系统字体渲染，同一字符在 macOS / Android / 掌机上形态差异极大，部分设备显示方框 |
| 字体图标（`icon.ttf`） | 项目自带的 Material Icons 子集只有 1028 个码位，`folder`/`settings`/`delete`/`search` 全部缺失 |
| 纯文字前缀（`[视频]`） | 就是「OSD 一堆文字堆在画面上」的根源 |

现在全部图标由 `ui::drawIcon()` 用 nanoVG 路径在 **24×24 坐标系**里绘制，
再按 `size` 缩放。好处是任何平台、任何分辨率、任何尺寸下完全一致，
且可以按需上色 / 调线宽，跟设计系统共用一套 token。

| 分组 | 图标 |
| :--- | :--- |
| 播放控制 | `Play` `Pause` `SeekBack` `SeekForward` `Prev` `Next` |
| 轨道与画面 | `Subtitles` `SubtitlesOff` `Audio` `Speed` `Aspect` |
| 音量 | `Volume` `VolumeMute` |
| 列表与导航 | `Playlist` `Back` `ChevronRight` `Folder` `Search` `Plus` `Close` |
| 媒体类型 | `Video` `Music` `Clock` `Drive` |
| 状态 | `Check` `Error` `Info` `Lock` `Unlock` `Brightness` `Plugin` |

线宽默认 2.0 逻辑像素，内部按 `strokeWidth / k` 反向换算（`k = size / 24`），
所以 40px 和 20px 的图标看起来是同一条线的粗细。所有端点 `NVG_ROUND`。

**新增图标**：加进 `enum class Icon`，在 `drawIcon()` 的 `switch` 里写路径。
画完用 `DECKPLAYER_FRAMEGRAB` 抓帧，在**目标尺寸**下看一眼 —— 24×24 里好看的
到 20px 可能糊成一团（`Aspect` 最初画成「外框 + 内条」，20px 下像银行卡，
改成双层同心描边才对）。

## 5. 列表卡片 `MediaCell`

主界面四个标签页、插件列表、对话框里的选项，全部用同一个卡片行。

```
┌──────────────────────────────────────────────────────────────┐
│▌ ┌────┐  01. 漂流 冒険の島!.mkv                    [已看 32%] │   ← 选中态：
│▌ │ ▶  │  24:13 · 1.2 GB · MKV                          ›    │     surfaceRaised 底
│▌ └────┘  ▬▬▬▬▬▬▬▬▬▬───────────────────────────             │     + accent 描边 1.6px
└──────────────────────────────────────────────────────────────┘     + 左侧 3×26 竖条
  ↑ 左侧强调竖条        ↑ 3px 续播进度条
```

| 部位 | 规格 |
| :--- | :--- |
| 行高 | **76**（含 12 间距时视觉节奏 ≈ 88） |
| 图标块 | 圆角 `radius::md`，边长 `clamp(h - 24, 32, 46)`，底色 `surfaceSunken` |
| 主文字 | `font::body`（17）+ `pal.text`，单行 `ellipsize` |
| 副文字 | `font::caption`（12.5）+ `pal.textDim`，与主文字间距 `space::xs` |
| badge | 右侧胶囊，`font::caption`，底色 `surfaceSunken`，文字 `textDim` |
| 续播进度条 | 高 3，轨道 `surfaceSunken`，填充 `accent`，左右内缩对齐文字 |
| 右箭头 | `ChevronRight`，16px，`pal.textMute` |
| 选中态 | 底 `surfaceRaised` + 描边 `outlineStrong` 1.6px + 左侧 `3×26` 的 `accent` 竖条 |

`MediaCell` 内部 `setHideHighlight(true)`，焦点框由自己画 —— borealis 默认的
白色高亮块在深色卡片上是「一整块白」，与设计语言冲突。

**图标只在选中行用强调色。** 早期版本整列图标都是橙的，一屏十几个橙色图标，
焦点反而淹没在里面；改成「未选中 = `textDim` 灰、选中 = `accent` 橙」之后，
视线自然被带到焦点上。同理，图标块的底色不随选中变成暖色 —— 橙色叠在
深蓝灰上会混成脏棕色，看起来像「禁用」。

### 5.1 分组标题 `SectionHeader`

高 46。左侧 `3×12` 的 `accent` 短条 + `font::caption` 的 `pal.textMute` 标题 +
`nvgTextLetterSpacing(0.6)` 的字距。字距是唯一「靠排版而非字号」拉开层级的手段。

### 5.2 空态 `EmptyState`

高 260。`64px` 圆形底（`surfaceSunken`）+ `Icon`（`pal.textMute`）+ 主文案
（`font::body`，`pal.textDim`）+ 说明（`font::caption`，`rgba(textDim, 0.78)`）。

空态必须是**可操作的提示**，不是空白：

| 标签 | 主文案 | 说明 |
| :--- | :--- | :--- |
| 文件 | 尚未添加媒体文件夹 | 按 添加 选择包含视频或音乐的目录 |
| 媒体库 | 没有找到视频文件 | 换个文件夹，或重新扫描 |
| 媒体库（音乐） | 没有找到音乐文件 | 换个文件夹，或重新扫描 |
| 历史 | 还没有播放记录 | 看过的内容会出现在这里 |

中文文案需要换行时**手动插 `\n`** —— nanoVG 不做自动折行，
靠宽度裁切会切出半行字。

### 5.3 缩略图变体（待落地）

行高 **72**，左侧改为 88×50 的 16:9 缩略图。文件类 / 设置类条目仍用图标块 ——
强行给它们配图只会更乱。

| 部位 | 列表（88×50） | 网格（约 243 宽） |
| :--- | :--- | :--- |
| 缩略图 | `radius::sm`（8） | 宽随列，`aspect-ratio: 16/9` |
| 进度条 | 压在缩略图底边，高 3，宽与图等宽 | 同左 |
| 标题 / 副标题 | `font::body` / `font::caption` | 14 / 12.5 |

**不做「横贯整行的进度条」。** 它会从缩略图右侧一直拉到卡片右缘，与右侧的
「已看 33%」是同一信息的两种表示，还额外切断了行的横向阅读线；压在图上就是
「这一格画面我看了多少」，语义才对。

缩略图本身取 `min(时长 × 0.1, 30s)` 处的一帧，不是第一帧 —— 见
`web/ui-review/README.md` 的说明。网格一屏 3 行 × 4 列，需要 8 张以上
互不相同的画面，否则循环会一眼看穿。

timeCenterY      = y + h - 34
transportCenterY = barCenterY - 64
settingsCenterY  = transportCenterY - 66

> **评审台已提案、实机尚未落地的一版**
>
> `web/ui-review/` 里正在评审的方案把上面这段改成：
>
> | | 现在 | 提案 |
> | :--- | :--- | :--- |
> | 底栏 | 238 | **168** |
> | 行数 | 设置行 / 主控行 / 进度条 / 时间 = 4 条基线 | 工具条 + 进度条 = **2 条** |
> | 主控行 | 居中于屏幕中线 `x = w/2` | 块左缘贴 `m`，块内播放按钮居中 |
> | 设置行 | 右对齐 `w − m` | 与主控块同一条 `toolCY = h − 124` |
> | 时间 | 独占一行 `h − 34` | 并进进度条两端，`12:34` 从 `m` 起、总时长右缘贴 `w − m` |
> | 进度条 | `m` → `w − m` | 两端各让出 62，让位给时间 |
>
> 触发原因：原来主控居中、设置右对齐、时间独占一行 —— 三条对齐轴互不相干，
> 左下角整片空白，观感就是「没对齐」。压成一条轴后底栏矮 70px，画面多露 70px。

> 落地前上表仍以代码为准；落地后要同步改本节。

### 6.2 控件清单

| 位置 | 控件 | 图标 | 尺寸 |
| :--- | :--- | :--- | ---: |
| 顶栏左 | 返回 | `Back` | 38 |
| 顶栏中 | 片名 + 「分辨率 · 硬件解码」信息行 | — | — |
| 顶栏右 | 时钟 | `Clock` + `HH:MM` | — |
| 设置行 | 字幕 | `Subtitles` / `SubtitlesOff` | 40 |
| 设置行 | 音轨 | `Audio` | 40 |
| 设置行 | 倍速 | `Speed` + 当前值胶囊（如 `1.5×`） | 40 |
| 设置行 | 画面比例 | `Aspect` | 40 |
| 设置行 | 播放列表 | `Playlist` | 40 |
| 设置行 | 锁定 | `Lock` / `Unlock` | 40 |
| 主控行 | 上一集 / 快退 10s / 播放暂停 / 快进 10s / 下一集 | `Prev` `SeekBack` `Play`\|`Pause` `SeekForward` `Next` | 46/40/64/40/46 |

播放按钮是**唯一的实心强调色控件**，也是唯一的主操作焦点。
其余按钮统一「深色玻璃底（`rgba(8,10,14,0.61)`）+ 1px 亮描边 + 亮色图标」。

> 玻璃必须**压暗**，不能提亮。第一版用 `rgba(255,255,255,0.09)` 的白色玻璃，
> 在彩条这种高饱和画面上等于没画：圆形底完全消失，只剩一根白线图标浮在
> 视频里，可见但不可读。压暗到 60% 黑之后，无论底下是纯黑还是纯白，
> 图标的对比度都稳定。

### 6.3 显隐动效

- 显示 / 隐藏为 **240ms 缓出**（`eased = 1 - (1 - t)²`），帧率无关插值。
- 顶栏上移 18px、底栏下移 18px，全部控件 alpha 联动。
- **不做逐帧 alpha 过渡的替代方案**：部分平台不逐帧重绘，会出现
  「有时有有时没有」的闪动，所以位移动画一律配合整体 OSD alpha。

### 6.4 拖动进度

- 按下进度条所在 46px 高的判定区才开始拖动（可视只有 5px，抓不住）。
- 拖动中：滑块直径从 12 放大到 18，加一圈 `accentSoft` 柔光；
  进度条正上方浮出时间气泡（`radius::md`，`font::detail`）。
- 拖动期间**不自动隐藏**，松手后重新计时。
- 松手才真正 `seek`，拖动过程只更新本地值（避免频繁 seek 卡顿）。

### 6.5 居中 HUD

播放/暂停、跳转、音量、亮度、倍速变化时出现：

```
┌────────────────────────┐   18 圆角，rgba(18,20,24,236)
│  ⏸   已暂停             │   左侧 accent 色图标 24px
└────────────────────────┘   右侧 font::body 文字
  ▬▬▬▬▬▬────────          带数值时（音量/亮度）追加 4px 进度条
```

显示 800ms，尾部 260ms 淡出。**不再是「一行中文文字」** —— 图标承担识别，
文字只给数值。

### 6.6 锁定态

锁定后所有控件隐藏，只保留画面。**必须有出路**：

- 单击 → 显示「触控已锁定 · 双击解锁」提示 2.6 秒（`lock_hint_until_`）。
- 双击 → 解锁。

原实现锁定后单击无任何反馈，触屏用户完全无法脱身。

| 操作 | 触屏 | 手柄 |
| :--- | :--- | :--- |
| 显示 / 隐藏 OSD | 单击画面空白 | — |
| 播放 / 暂停 | 双击画面，或点主控按钮 | A |
| 拖动进度 | 按住进度条拖动 | ← → |
| 快退 / 快进 10s | 点两侧小圆 | ← → |

### 6.8 自动隐藏

显示后 **8 秒**无操作隐藏；拖动进度、打开对话框、锁定提示期间不计时。
隐藏时**清空触摸命中区** —— 否则会点到看不见的按钮。

### 6.9 音量与亮度（对齐 wiliwili）

**音量是必需品，不能被触屏独占** —— 没有触摸屏的掌机上，那等于没有音量控制。

| 输入 | 音量 | 亮度 |
| :--- | :--- | :--- |
| 手柄 | `LT` / `RT`，±5，`allowRepeating` 按住连发 | 无绑定（设备级设置） |
| 触屏 | 右半屏上下滑 | 左半屏上下滑 |

两条路径都走同一个 `setVolume()`，HUD 表现一致（第 6.5 节）。

> **为什么不做 wiliwili 的「RT + ↑↓」组合键**：wiliwili 的 OSD 是焦点式 borealis
> 控件树，↑↓ 是空闲的；本项目 OSD 是自绘、`↑` 已给「播放列表」，再用组合键就等于
> 又造一个「按住 + 方向」的双义手势 —— 正是第 6.6 节要避免的东西。
> 扳机只有一个语义、且天然是模拟量，更适合连续调节。

> **亮度不做「蒙层冒充背光」**：`canSetBacklightBrightness()` 为真时直接调系统背光
> （Steam Deck / 安卓 / Switch），为假时才退回黑色蒙层（桌面 macOS，抓帧与开发用）。
> 蒙层只会压暗亮部、吃掉暗部细节，且没有一个像素真的变暗。

### 6.10 字幕面板

点 OSD 的「字幕」按钮（或 `S`）从右侧滑出，宽 324，距右缘 `m`、距底 186
（让开工具条）。**面板挂在 `.osd` 之外** —— OSD 8 秒后会收起，用户正在挑字幕
时不能被收走。

```
┌──────────────────────────────┐
│ 字幕                      ✕  │
├──────────────────────────────┤
│ ⊘ 关闭字幕                    │
│ ▣ 简体中文      内嵌 · ASS  ✓ │
│ ▣ English      内嵌 · SUBRIP  │
│ ▣ <片名>.chs   外挂 · …      │   ← 加载后才出现
├──────────────────────────────┤
│ ＋ 从文件加载…                │   虚线 accent 框
├──────────────────────────────┤
│ [−0.5s]   延时 0.0s   [+0.5s] │
├──────────────────────────────┤
│ 外挂字幕不会覆盖内嵌轨…        │
└──────────────────────────────┘
```

永久暗色，不跟浅色主题 —— 它浮在视频画面上，浅底控件遇亮场景会消失
（与 6.2 节玻璃必须压暗是同一条理由）。

**为什么「从文件加载」是文件选择器而不是输入框。**
实机现在是 `promptLoadExternalSubtitle()` 弹 IME，让用户在掌机上手打
`/run/media/mmcblk0p1/Videos/Movie.2024.2160p/movie.chs.ass` —— 实际不可用。
`loadExternalSubtitle()` 本身是对的（`sub-add <path> select`，新增 external
轨、不替换内嵌轨），缺的只是「怎么选到这个文件」。

做法：把 `FolderPickerActivity` 泛化成 `FilePicker`。

```cpp
enum class PickMode { Folder, File };
FilePickerActivity(PickMode mode,
                   const std::vector<std::string>& extensions = {},
                   OnPick on_pick);
```

`File` 模式只列 `.srt/.ass/.vtt/.sup/.ssa`，**默认停在当前视频所在目录** ——
同名字幕 90% 的情况已经在那里了。选择器样式：620 宽、56 行高、与片名匹配的
文件置顶并标「同名」。

`MediaItem::matched_subtitles` 在扫描时已经填好（卡片上显示「含字幕」），
所以「自动加载同名外挂字幕」只需在打开文件后遍历一次，不需要重新扫描。

侧边栏度量由 `deck_theme.cpp` 的 `brls::Style::addMetric()` 覆盖：

| 度量 | 值 | 原值 | 说明 |
| :--- | ---: | ---: | :--- |
| `tab_frame/sidebar_width` | 300 | 410 | 410 占 1280 的 32%，太胖 |
| `sidebar/padding_left` | 48 | — | 与内容区左边距对齐 |
| `item_height` | 62 | — | 触屏可点 |

| `item_accent_rect_width` | 3 | — | 与 `MediaCell` 竖条同宽 |
| `applet_frame/header_height` | 92 | — | |
| `header_title_font_size` | 29 | — | |
| `footer_height` | 64 | — | |
| `highlight/corner_radius` | 14 | 6 | 与 `radius::md` 统一 |
| `highlight/stroke_width` | 2 | 5 | 2px 更接近硬边框而不是发光圈 |

> **评审台提案：160 / 26 / 56 / 17，条目带 18px 图标。**
> 300（23.4%）→ 216（16.9%）→ 160（12.5%）。两次收窄的教训不一样：
> 第一次是数字太胖；第二次发现 216 仍然显空 —— 四个汉字条目只占 51px，
> 右边 100 多像素没有任何东西，观感上的「宽」来自**内容撑不起来**。
> 加图标之后同样的宽度有了密度，才能收到 160。
> 实机尚未改，以代码为准。

> **没有 `brls/highlight/padding` 这个度量。**
> borealis 的高亮内缩是 `View` 的成员 `highlightPadding`（从 XML 属性
> `highlightPadding` 读），`addMetric()` 塞同名键不会有任何效果 —— 这个坑
> 实际踩过：加了三行度量，抓帧发现对话框按钮的高亮依旧顶满整条 720px。
> 对话框按钮的内缩直接写在 `external/borealis` 的 `dialogXML` 上
> （`highlightPadding="6"`），因为它是 vendored 且只此一处。

所有列表 `setPaddingBottom(28)`，否则最后一行被底部提示栏硬切。
滚动条统一走 `styleScrollingFrame()` 调成 `rgba(255,255,255,24)` ——
borealis 默认是白色 4px / 0.3 alpha，看起来像一条来路不明的分割线。

### 7.3 对话框（字幕 / 音轨 / 播放列表）

- 头图 `SectionHeader`（如「字幕轨道 · 3 项」）。
- 主体 `MediaCell` 行，行高 64。
- 当前项用 `使用中` / `播放中` badge，不用对勾（对勾在 14px 下太小）。
- **高度贴合内容**：`contentHeight(list, max)` 按子视图高度求和后 `min(..., max)`。
  固定 420 会让 3 条内容拖出一个大黑框。

### 7.4 插件管理

`makeRow()` 工厂 + `SectionHeader` / `EmptyState`。

在行回调里调 `popActivity()` 会把整个 Activity 关掉。

换字体时选了 **Noto Sans SC 可变字体（VF）**，现象：

```
有中文文字的 OSD  → 视频区域 100% 纯黑
去掉中文文字      → 视频正常
```

**根因**：nanoVG 的 `stb_truetype` 不支持可变字体（`fvar` 表）。
渲染中文时字形解析失败，**整个 nanoVG 帧被丢弃**，于是 mpv 已经画好的视频
也被一并丢弃 —— 表现为「加个中文标签，视频就没了」。

**修复**：用 `fonttools` 的 `instantiateVariableFont` 实例化到 `wght=400`：

```python
from fontTools.ttLib import TTFont
from fontTools.varLib.instancer import instantiateVariableFont
f = TTFont('variable.ttf')
inst = instantiateVariableFont(f, {'wght': 400}, inplace=False)
inst.save('static.ttf')       # 无 fvar、有 glyf、无 CFF
```

**选字体的三条硬性要求**：

| 要求 | 检查方式 | 违反后果 |
| :--- | :--- | :--- |
| 无 `fvar` 表 | `'fvar' in f.keys()` | 整帧渲染失败 |
| 有 `glyf` 表（TrueType 轮廓） | `'glyf' in f.keys()` | CFF/OTTO 不支持 |
| 覆盖中文 | cmap 中 CJK ≥ 20000 | 缺字显示为方块 |

`scripts/check_font.py` 可一键校验。

### B1：OSD 所有文字都画不出来

### B3：A 键被 `registerClickAction` 覆盖

borealis 的 `registerAction` **按按钮去重**（`view.cpp:770-774`），
