# 实施顺序

每批可以单独评审。使用真实项目类编写回归测试，新建测试文件时按 `tests/run_tests.sh` 的 `TESTS` 登记。改 Borealis 焦点和异步回调前先阅读 `AGENTS.md` 中有关 Tab 销毁、延迟恢复焦点及存活标志的说明。

## 第一批　片库数据与续播

| 工作项 | 建议落点 | 交付判据 |
|---|---|---|
| 展示标题与原名搜索 | `LibraryViewOptions::apply` 和共用的标题选择逻辑。保留自然排序和媒体路径身份。 | 搜「蓝调时刻」和 `cam_0042` 返回同一条文件；排序与展示标题一致；原名匹配可在副文本辨认。 |
| 最近添加 | `MediaLibrary::getRecent` 与总览调用方。保存首次入库时间，既有缓存保留兼容读取；升级时明示旧条目缺历史入库时间的回退规则。 | 默认名称排序不会再次打散该栏目。今天拷贝且保留旧修改日期的影片排在上方。重复扫描不刷新首次入库时间。 |
| 正确的剧集身份 | `SeriesDetector` 传递真实季号、集号及同剧证据；`SeriesActivity` 读取该信息。保留 OP/ED、无编号素材和独立视频的可访问性。 | S01E05 与 S01E08 显示真实集号，赛车录屏仍属独立视频；完成与未看完的记录各有正确主动作。 |
| 共用续播资格 | 将列表、剧集页和 `PlayerActivity` 对「可续播」的判断统一。建议这一批沿用现有 `>15 秒` 且未完成的播放规则。 | 12 秒和恰好 15 秒显示「最近打开」并从头播放；18 秒显示并实际恢复至 18 秒；已完成项无「继续播放」误导。 |

## 第二批　默认总览与手柄导航

1. 在 `renderLibraryOverview()` 接入第一批的展示结果。处理空库、无历史、有历史、已完成及来源离线。沿用现有历史存储和播放后端。
2. 把默认视频目录与其他探测位置的选择说明白。用户确认前能看到路径；音乐、下载和额外 SD 卡位置可分别选择。
3. 为目录栈保存媒体路径或稳定标识及滚动位置。缩略图到达与用户返回走同一套身份恢复逻辑。小屏将侧栏和低频工具折叠，列数按实际可读宽度计算。
4. 交付 1280×800 有历史首页、关闭抽帧的冷缓存首页、640×360 小窗和大字档截图。跑通两条原生冒烟路径：空历史进文件夹，有历史一键续播。

## 第三批　掌机内测

用 Steam Deck 游戏模式和 TrimUI Smart Pro 各执行一次验收表。按设备记录运行构建、固件、硬解、字幕、30 分钟播放、休眠唤醒和拔插卡结果。两台设备可分别放行；记录阻断的机型和片源特征。
