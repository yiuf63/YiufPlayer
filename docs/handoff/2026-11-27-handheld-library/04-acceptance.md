### 实施中发现的、交接文档未记录的问题

1. **`check_docs.py` 的续播检查会静默失效**
   它 grep 字面量 `"rec.position > 15"`。把阈值收进 `kResumeMinSeconds`
   常量后该字符串不复存在，检查永远通过（且看起来像「文档写错」）。
   已改为校验三项：常量已定义、判定使用常量、文档秒数与常量一致。

2. **`metadata.dat` 的分隔符是 `0x1f`，不是竖线**
   我按 `path|title|...` 准备测试数据时，元数据静默不加载，
   现象和「搜索坏了」完全一样。已写进 `check_search()` 的注释。

3. **一条被推翻的判断（重要，避免后人重走）**
   我一度认为「默认总览下搜索框完全无效」，并准备作为缺陷提交。
   抓帧对比「apply 传 / 不传 query」两版，结果都是 6.64（有内容），
   推翻了该判断 —— `renderLibraryContent()` 里
   `flat = !library_query_.empty() || ...` 会强制切到平铺视图，
   而平铺分支本来就传了 query。**搜索一直是有效的。**
   最终保留「显式传参」作为防御性改动，但注释写的是真实原因。

### 最近添加的真实验证（用真实文件与真实缓存跑的）

用 mtime 分别为 2019 / 2022 / 2024 的三个真实文件：

```
首次扫描（三个文件同一时刻入库）
  a_old.mp4    mtime=1546272000(2019)  first_indexed=1795769608
  m_mid.mp4    mtime=1640966400(2022)  first_indexed=1795769608
  z_new.mp4    mtime=1704038400(2024)  first_indexed=1795769608
```

- **重扫不刷新**：间隔 3 秒再启动，三个 `first_indexed` 全部未变 ✅

旧缓存升级（手工放一份 v2 的 6 列缓存）：

```
升级前  # Muvik library cache v2      / 6 列
升级后  # Muvik library cache v3      / 含 first_indexed
        a_old  first_indexed=1546272000  ← 等于其 mtime，不是「现在」
第二次启动 md5 不变（不会反复写盘）  ✅
```

> 期间发现一个交接文档没记录的问题：**旧缓存永远不会升级**。
> `save()` 只在扫描和「添加目录」时调用，纯启动不回写，
> 兜底只存在内存里。已修（`bcb47e7`）。

### 尚未覆盖

- 续播边界：单测覆盖 12/15/18 秒判定，**没有真机按这三种时长实际播放**。
- 多文件陆续入库的场景（先扫描 A，再拷入 B，再重扫）没有走通：
  程序只在库为空或目录为空时自动扫描，库非空时需用户按 Y，

- 全部结果来自 macOS arm64。Deck 与 TrimUI 真机仍为「待真机」。

### 修掉的一个真实缺陷（设计稿未提及）

`ResumeHero` 构造时用 `sceneImageReady()` 判断有没有封面 —— 它查的是
nanoVG 图片句柄，而句柄只在 `drawScene()` 里懒加载。构造期必然返回 false，
于是**缩略图文件就在缓存里，首页却永远显示无图态**。

实测日志：

```
[HERO] path=/tmp/hero/media/big_show.mkv
       thumb=/tmp/hero/cfg/yiufplayer/thumbnails/3b2d2f.rgba
       ready=false          ← 文件在，句柄没有
```

新增 `sceneImageFileExists()`（存在且 >128 字节），内联实现以便脱离
nanoVG 单测。两个函数的语义差异已写进 `scene_tile.hpp` 注释。

## 第二批补充：焦点验证（`be976d8`）

上一版把「焦点按身份恢复」标为**已实现但未验证**。补验证的过程中发现
实现本身有一个真缺陷。

### 缺陷：换层后焦点落在错的条目

```
在总览横向移到第 3 张目录卡 d3 → 按 A 进入 → 按 B 返回
期望焦点：/tmp/smoke3/d3（目录卡）
实际焦点：/tmp/smoke3/d3/ep_d3.mp4（「最近添加」里那部片的行）
```

根因：**同一个文件在两层里的身份字符串相同**。

| 位置 | identity |
| :--- | :--- |
| 文件夹内那一行 | `/path/d3/ep_d3.mp4` |
| 总览「最近添加」 | `/path/d3/ep_d3.mp4` ← 同一个 |

`openFolder()` 记录时读「此刻焦点」（还停在旧层），带进新层查找，
匹配到了总览里同名的媒体行。

修法：换层时改用**目标层**记录的身份（`pending_focus_identity_`）。

### 新增的可验证性接口

| 接口 | 用途 |
| :--- | :--- |
| `focusedIdentityForTest()` | 读出当前焦点代表的条目路径 |
| `rememberedIdentityForTest()` | 读出某层记录的身份 |

没有第一个接口，测试只能断言「有焦点」—— 按序号和按身份两种实现
都能通过，那就是一条恒真的测试。

### 冒烟实测

```
PASS  横向移动后身份 = /tmp/smoke3/d3（应为目录卡路径）
PASS  按 A 进入了该目录
PASS  返回后焦点仍在原来那一项（稳定态）
```

**还原验证**：临时禁用身份恢复后立即变红：

```
FAIL  返回后焦点仍在原来那一项（稳定态）  期望[/tmp/smoke3/d3] 实际[/tmp/smoke3/d2]
```

`d2` 正是按序号（取 idx=0/1）会落到的位置，说明这条测试能区分两种实现。

### 调试中记下的两个坑

1. **同一步内连续 `injectButton` 之间没有帧间隔**。冒烟脚本的 `delay_ms`
   只在步骤之间生效。进/出放在同一步里会读到旧焦点，已拆成两步。
2. **`focusedIdentityForTest()` 不要向上爬父节点**。最初爬 4 层，
   结果爬到祖先链里另一行上，报出与当前焦点无关的路径。
   三个卡片类本身都可聚焦，焦点必然直接落在它们上面。

### 仍未覆盖

- 「异步缩略图刷新后焦点仍正确」：本次验证的是进/出文件夹，
  没有覆盖「缩略图到达触发重建」这条路径。不过 `renderLibraryContent()`
  末尾的接回逻辑已改为优先按身份，理论上覆盖了该场景，**但没有实测**。
- 多屏（需要滚动）的长列表未覆盖：测试素材只有 3 个目录，一屏放得下。

## 第三批执行记录（`c8837d8`）

### 做了什么

我一度判定「640×360 下最后一条内容被截断看不到」——末条落 y=338~350，

两个分辨率一致 → 这是「内容可滚动、初始停在底栏下方」的正常行为，
不是小屏缺陷。留白改动保留（给滚动余量），但注释写的是真实原因。

### 未做：按内容区重排列数

设计稿（02-ux.md）要求「跨页复用列数计算，输入为可用宽度、基础字号、

真正缺的是**字号档位**——那是一个新功能（设置项 + 全局字号缩放 + 各视图

## 字号档位（`d06985f`）

### 为什么先做这个

02-ux.md 要求「按可用宽度、基础字号、观看距离档重排列数」。
核对项目后，前两项都不成立：

- `Application::contentWidth` **恒为 1280**，物理分辨率只影响 `windowScale`
- 没有字号档位机制

而「布局与分辨率无关」是本项目已验证的特性（README 第 29 轮：
五种分辨率布局形状差异 < 1 个百分点）。所以按分辨率算列数没有意义。
**缺的输入是字号**，先补它。

### 三档

| 档位 | 系数 | 用途 |
| :--- | ---: | :--- |
| 紧凑 | 0.85 | 小屏 / 远距离 |
| 标准 | 1.00 | 默认，按 40cm 握持距离设计 |
| 大字 | 1.20 | 近距 / 视力不便 |

上下限 0.85~1.30：再小 caption 约 10.6px 会糊，再大一行放不下两个中文词。

### 覆盖范围（第一版只改了自绘文字，差异 0.796，用户看不出）

| 层 | 处理 |
| :--- | :--- |
| 自绘文字（卡片/续播块/列表行） | 本来就走 `ui::font` token |
| 主题度量（侧栏 18、标题栏 29） | 改为 `× scale` |
| `style_applied` 守卫 | bool → 比较缩放值（原来只应用一次） |
| 4 处硬编码字号（26/15/16/13） | 改为走 token |

补齐后两档差异 1.53~1.55。

### 抓帧标定（阈值不是拍的）

| 状态 | 两档整图平均差 |
| :--- | ---: |
| 全部生效 | 1.53 ~ 1.55 |
| 只自绘文字生效 | 1.12 |
| 完全不生效 | 约 0.1 |

阈值定在 **1.35**。最初写 1.0，实测发现它区分不了
「全部生效」和「只生效一部分」—— 而那正是这条检查最该抓住的模式。
